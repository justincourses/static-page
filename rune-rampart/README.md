# 符文守护

“符文守护”是一个无框架、开发时无需构建的三消 × 塔防浏览器小游戏。游戏使用原生 HTML、CSS 和 JavaScript，打开静态服务器即可游玩；Cloudflare Pages 发布流程会额外整理一份干净的 `dist/` 目录。

## 开始游戏

直接双击 `index.html`，或在本目录启动静态服务器：

```bash
python3 -m http.server 4173
```

然后访问 <http://localhost:4173>。

## 玩法

- 每完成一组消除获得 1 点补强；四连额外 `+1`，五连及以上额外 `+2`，铸币组再额外 `+1`。补强会按当前升级策略强化军械，初次升级消耗 26 点，之后每次增加 3 点，最高 56 点。
- 红曜石：每枚储备 1 次余烬齐射（最多 24 次）。弩炮开火时整轮弹丸伤害提高 25%，并消耗 1 次。
- 蓝晶：每枚转化 2 点奥能，连续坠落会提高收益；消耗 18 点可点击“奥术齐射”或按 `Q` 攻击全场。
- 绿晶：立即修复城墙，只记录实际恢复的耐久；城墙已满时不会产生虚假的修复数值。
- 铸币：除了颜色收益外，铸币消除组额外获得 1 点补强。
- 连续坠落会放大奥能、修复与军功收益，不会重复放大补强，方便玩家直接估算升级进度。
- 弩炮持续追踪距离城墙最近的目标。敌人抵达城下后会扣除城墙耐久。
- 敌人防御会降低弩炮和奥术齐射伤害。城防等级会降低敌军突破时造成的伤害。
- 每波都有建议消除组数。玩家需要安排余烬、奥能、补强和修复资源，才能跟上后期压力。
- 所有资源增加和消费都会在对应 HUD 上显示 `+N` 或 `-N`，并配合战场浮字、日志、进度条或弹丸特效；资源已满时会明确显示“已满”。
- 萌新与大佬难度在第 100 波肃清后完成战役；无限难度持续到配置上限第 99,999 波。

## 难度

欢迎界面提供三个难度，并默认选择萌新。右上角的“战役选项”按钮会暂停当前战局并重新打开欢迎界面；确认出征会按所选难度重开游戏。

- 萌新：每波建议消除约 5 组起，高阶怪占比从约 45% 起步，彩蛋数量适中，中期开始出现双批次敌潮，通关上限为 100 波。
- 大佬：每波建议消除约 6 组起，高阶怪占比从约 64% 起步，彩蛋最稀少，后期最多同时出现 4 个敌人，通关上限为 100 波。
- 无限：每波建议消除约 5 组起，高阶怪占比从约 52% 起步，通关配置上限为 99,999 波。排行榜优先比较守完波数。

所有难度都会在每一波提高敌军生命、攻击、防御与速度。每 10 波包含一次 Boss 战；下一波进入新的压力阶段，并额外提高敌军规模与出怪批次。萌新与大佬的第 100 波会同时出现 3 头 Boss。

大佬难度使用一条面向理想操作校准的极限曲线。平衡模型要求玩家达到每波建议消除量，并合理使用余烬齐射、暴击、奥术齐射、彩蛋符文和均衡补强；模型中的 95% 效率会在第 100 波前失守。

## 敌军与彩蛋效果

- 速度型拥有较低生命和防御，但会快速逼近城墙。
- 攻击型携带重斧，突破防线后会造成高额伤害。
- 防御型移动缓慢，拥有高生命和高防御。
- 均衡型的各项能力较为平均。
- Boss 拥有独立外观、首领预警和更高的综合属性。

少数敌人会携带彩蛋符文，新掉落的符文方块也有概率获得彩蛋标记。击败彩蛋怪或消除彩蛋方块后，弩炮会在有限攻击次数内获得爆裂范围伤害、霜缚减速或破甲效果。多个彩蛋会按触发顺序排队，当前效果耗尽后自动生效下一项；战场左上 HUD 下方会显示当前效果、剩余攻击次数和候命数量。难度越高，敌人与棋盘中的彩蛋概率越低。

## 升级与控制

补强默认使用“自动”策略，并优先补齐最低等级的装备。你可以随时切换为攻击、防御或攻速优先；选择会持续影响后续补强，直到重开游戏。战场左上角以微型 HUD 显示攻击、防御与攻速，完整军械数值紧凑排列在“下一次升级”模块下方；当前威胁位于右上角，彩蛋符文状态位于微型 HUD 下方，军情位于战场左下角。

攻速等级不仅缩短等效攻击间隔，也会改变发射表现。攻速达到 4、7、10 级时，弩炮会依次解锁双连发、三连发和四连发；额外弹丸使用较低单发伤害，因此多发动画不会破坏既有战役平衡曲线。

- `Q`：发动奥术齐射。
- `Esc`：暂停或继续游戏；欢迎界面打开时会关闭该界面。
- 右上角按钮：打开战役选项、进入或退出全屏、开关 MIDI 配乐、切换战斗音效、暂停或继续游戏。

## 本地存档与续战

游戏会在当前浏览器的 `localStorage` 中保留最后选择的难度、音效/配乐开关和未完成战役。每一波开始时会写入稳定检查点；主动暂停、切到后台或离开页面时会更新当前棋盘、资源、装备、敌军位置和生命值、彩蛋队列等状态。如果页面恰好在三消动画中关闭，则继续保留该波开始时的稳定检查点，避免恢复出残缺棋盘。

下次打开游戏时会先显示未完战报，玩家可以继续保存的波次，或归档旧进度并回到难度选择界面。战败、达到当前难度的通关上限或主动重新部署后，旧战役进度会被清除；最后一次选择的难度仍会保留。旧版“新手”存档会自动迁移到萌新难度。存档不会上传到服务器，也不会跨浏览器或设备同步。

## 配乐与音效资源

背景音乐由 Web Audio 按 MIDI 音符序列实时合成，使用独立开关，并在暂停、切到后台、战败或结算时停止。这样无需下载 MIDI 播放器依赖，也能保持体积轻量；浏览器首次允许音频播放后，配乐会随战斗开始。

游戏使用少量本地音效，并通过 Web Audio 叠加连锁升调与战场反馈。所有外部音效来自 Kenney，采用 Creative Commons CC0 许可：

- [Kenney UI Audio](https://kenney.nl/assets/ui-audio)
- [Kenney Impact Sounds](https://kenney.nl/assets/impact-sounds)

原始许可文本保存在 `assets/audio/ui/License.txt` 与 `assets/audio/impact/License.txt`。

## 文件

- `index.html`：页面结构与游戏界面。
- `styles.css`：响应式布局、战场插画和动画。
- `game-config.js`：难度参数、默认难度和各难度通关波次上限。
- `game.js`：三消、资源、装备、波次和战斗逻辑。
- `tests/browser_smoke.js`：Playwright 浏览器冒烟测试。
- `wrangler.jsonc`：Cloudflare Pages 项目名称、输出目录和兼容日期。
- `scripts/build.mjs`：生成只包含公开静态资源的 `dist/` 目录。
- `package.json`：NVM/Node 约束、Wrangler 依赖和本地预览/发布命令。

## 浏览器验证

安装 Playwright 后，启动静态服务器并运行冒烟测试：

```bash
node tests/browser_smoke.js
```

测试会覆盖三档难度、各难度通关上限、无限模式越过第 100 波、逐波增强曲线、排行榜波次排序、理想操作平衡模型、补强奖励公式、自动和定向升级、余烬与奥能的可感知消费、三消动画、四类普通怪与 Boss、炮口发射坐标、彩蛋攻击队列、波次/暂停存档、继续与重新部署流程、MIDI 配乐开关、战役胜利结算、欢迎界面重开、暂停控制、14px 最小字号和移动端横向溢出。

## 发布到 Cloudflare Pages

项目使用 `wrangler.jsonc` 作为 Cloudflare Pages 配置源，Pages 项目名为 `rune-rampart`。构建脚本只会把浏览器运行所需的 HTML、CSS、JavaScript 和音效资源复制到 `dist/`，不会上传测试文件或本地开发依赖。

项目通过 `.nvmrc` 跟随 NVM 当前的 Node.js LTS，不固定具体小版本。首次使用时，通过 NVM 切换 Node 版本、安装依赖并登录 Cloudflare：

```bash
nvm install
npm install
npx wrangler login
npx wrangler pages project create rune-rampart --production-branch main
```

启动本地 Pages 预览：

```bash
npm run dev
```

构建并发布：

```bash
npm run deploy
```

如果需要创建分支预览，可以先运行 `npm run build`，再执行：

```bash
npx wrangler pages deploy ./dist --project-name rune-rampart --branch <BRANCH_NAME>
```

Wrangler Direct Upload 项目之后不能直接切换为 Pages Git 集成。如果未来需要由 GitHub 或 GitLab 自动部署，请新建一个采用 Git 集成的 Pages 项目。
